# Security Policy

## Supported versions

Security fixes are developed for the latest published CaprICE release. Update to the latest release before reporting an issue when possible.

## Reporting a vulnerability

Please do not report suspected vulnerabilities in a public issue or include exploit details, credentials, personal data, or unredacted logs.

Use GitHub's **Report a vulnerability** option on this repository's **Security** tab to submit a private report. Include:

- The affected CaprICE version and Windows version.
- A concise description of the impact and the conditions required.
- Minimal reproduction steps that do not expose real user data.
- Any relevant logs only after removing tokens, URLs containing credentials, prompts, and personal information.

If private vulnerability reporting is unavailable, open a public issue asking the maintainers for a private reporting channel. Do not include technical details until a private channel is established.

We will review reports and coordinate a fix and disclosure with the reporter. Response and remediation timelines depend on severity and maintainer availability; no fixed service-level agreement is offered.

CaprICE inspects AI request context and writes local audit data. Treat logs and diagnostic files as potentially sensitive; redact them before sharing.

## Politique de sécurité

### Versions prises en charge

Les correctifs de sécurité sont préparés pour la dernière version publiée de CaprICE. Si possible, mettez l'application à jour avant de signaler un problème.

### Signaler une vulnérabilité

Ne publiez pas de vulnérabilité présumée dans une issue publique. N'incluez pas d'étapes d'exploitation détaillées, d'identifiants, de données personnelles ni de journaux non expurgés.

Utilisez l'option GitHub **Report a vulnerability** dans l'onglet **Security** du dépôt pour envoyer un signalement privé. Indiquez la version de CaprICE et de Windows, l'impact, les conditions nécessaires, ainsi que des étapes de reproduction minimales ne contenant aucune donnée réelle. Expurgez les jetons, identifiants présents dans les URL, prompts et informations personnelles des journaux.

Si le signalement privé n'est pas disponible, ouvrez une issue publique demandant un canal privé, sans publier de détails techniques. Les délais de réponse et de correction dépendent de la gravité et de la disponibilité des mainteneurs ; aucun délai garanti n'est annoncé.

CaprICE inspecte le contexte des requêtes IA et écrit des données d'audit locales. Considérez les journaux et fichiers de diagnostic comme potentiellement sensibles et expurgez-les avant tout partage.
